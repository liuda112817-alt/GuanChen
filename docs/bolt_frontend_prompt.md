# 观尘｜Bolt 前端生成 Prompt

下面整段可以直接复制给 Bolt。产品名称只使用“观尘”，界面、页面标题、代码中的产品文案都不要出现 “V2”“GuanChen v2” 或“二代”。

---

## 你的任务

请为“观尘”制作一个可实际连接后端的、移动端优先的 React + TypeScript 网页应用。观尘是一个传统文化视角的思考工具，帮助用户把复杂问题先看清楚，再回到现实做选择。它不是算命直播间，不是神秘主义游戏，也不是医疗、法律或投资决策替代品。

第一版必须是真实可用的前端：使用 API 适配层连接 FastAPI 后端；后端不可用时可以提供开发态空状态，但不要把假数据写死到正式交互里。将 API 地址放在 `VITE_API_BASE_URL`，默认值为 `http://127.0.0.1:8000`。

## 产品气质

观尘的表达要有一点“松弛、机锋、看得开”的感觉：像一个见过些事、愿意把复杂问题讲明白的人。只借鉴抽象气质，不模仿任何具体影视人物，不使用影视台词、口头禅或角色身份。

界面和模型回答必须像同一个产品：

- 先回应问题，再展开依据；
- 口语自然，偶尔轻巧，但不油滑、不卖关子、不故作高深；
- 让复杂信息变得好读，避免密密麻麻的术语墙；
- 传统文化是观察角度，不是判决书；
- 现实建议保持可验证、可逆、分阶段；
- 危机、医疗、法律、投资场景切换为直接、温和、严肃的安全表达，禁用玩笑和玄学装饰。

推荐 UI 文案：

- 空状态：`先说说你眼前这件事。别急，咱们一层层看。`
- 等待输入：`还差一点资料，补上再往下看。`
- 六爻确认：`先别急着落子，咱们把问题再对一遍。`
- 普通加载：`正在把这件事捋顺……`
- 检索完成：`资料看过一遍了，正在整理重点。`
- 安全拦截：`这件事先不走推演，我们回到现实里处理。`

不要使用：`大师`、`神断`、`改命`、`保证`、`注定`、`必然`、`今日运势爆表`、`你的命运已经被看穿`。不要让界面出现“AI 正在思考”或任何思维链内容，只展示友好的进度状态。

## 视觉方向

做成“当代东方的安静工具”，不是古风景区，也不是赛博玄学。

- 主色：墨黑 `#182024`、雾白 `#F7F5F0`、青黛 `#356B6A`。
- 强调色：温和朱砂 `#C96B52`，只用于主要操作、警示和选中状态，不要大面积铺红。
- 辅助色：竹青 `#A9C5B5`、砂金 `#C7A66A`，用于轻微高亮、引用标签和进度点。
- 背景允许有非常轻的纸张颗粒或尘点纹理，不能使用明显的宣纸边框、龙凤、八卦阵、金色神殿、发光水晶球等陈旧占卜视觉。
- 卡片圆角 16–20px，边框低对比度，阴影柔和；保持大量留白。
- 字体优先使用系统中文字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 动效短、轻、可中断：进度点、卡片展开、引用抽屉、确认卡片出现可以有 160–240ms 的过渡；不要持续漂浮、闪烁、旋转或自动播放背景。
- 默认支持浅色和深色模式，跟随系统并允许用户切换；深色模式保持低饱和，不要纯黑背景配刺眼金色。
- 所有图标使用 Lucide 或同一套线性图标；不要混用 emoji 作为主要 UI 图标。

## 页面与布局

### 1. 首页 / 对话页

这是主页面，桌面端采用左侧窄导航 + 中间对话区 + 右侧可收起上下文栏；小屏只保留顶部导航和对话区。

左侧导航：

- 观尘 Logo 和一句短标语：`把复杂的事，先看清楚。`
- `新问题`
- `历史会话`
- `我的资料`
- `使用说明`
- 浅色/深色切换

对话空状态：

- 标题：`今天想看清楚什么？`
- 副文案：`可以问传统文化，也可以直接说你的现实困惑。`
- 四个示例入口：`正官是什么意思？`、`帮我看看这个梦`、`我的八字事业如何`、`我在考虑要不要换工作`
- 示例入口只填入输入框，不要直接发送。

输入区：

- 多行 textarea，Enter 发送，Shift+Enter 换行；移动端使用发送按钮。
- Placeholder：`说说你正在面对的事……`
- 发送按钮文字使用 `发给观尘`，加载时改为 `整理中`。
- 不在首次打开时弹出生资料表单。
- 输入区上方显示当前会话的小状态，例如 `普通对话`、`八字资料待补充`、`六爻确认中`。

消息气泡：

- 用户消息靠右，使用墨色或青黛色实底，文字高对比度。
- 观尘消息靠左，使用雾白/深色面板，顶部显示轻量 Agent 标签，如 `知识`、`八字`、`梦境`、`六爻`；不要暴露内部路由枚举、Trace ID、模型名或 Tool 名。
- Markdown 安全渲染：支持段落、列表、粗体、代码块和链接；禁止将模型文本作为 HTML 直接注入。
- 回答中的 `facts` 用折叠的“确定事实”区域展示，前端只展示后端返回内容，禁止自行计算或改写八字/卦象数据。
- 回答中的 `citations` 显示为来源胶囊；点击后打开右侧抽屉或底部 Sheet，展示标题、章节和原文；如果后端未来提供 `source_type` 再显示来源类型。原文与观尘的解释必须视觉区分。

### 2. 历史会话

显示会话时间、最近一句摘要和当前状态。点击后调用 `GET /api/v1/sessions/{session_id}` 恢复消息、最后回答和确认卡片。加载失败时给出“重新加载”和“新问题”，不要清空本地凭证。

### 3. 我的资料

资料页只在用户主动打开或后端返回 `needs_input` 时使用。支持增量填写和更正，清晰标注“已提供”和“还缺什么”。不要把出生资料描述成决定命运的个人标签；标题使用 `出生资料`，辅助文案使用 `只用于需要它的八字问题`。

### 4. 使用说明

用三张简洁卡片说明：

1. `先问问题`：知识、梦境、八字和现实决策都可以从自然语言开始。
2. `需要时补资料`：只有八字真正需要时才请求出生资料。
3. `回到现实做选择`：六爻和传统文化只提供反思角度，不替代专业意见或用户判断。

## 后端连接合同

### 会话凭证

应用启动后先调用：

```http
POST /api/v1/sessions
```

保存返回的 `session_id` 和 `session_token` 到 `sessionStorage`。后续请求统一携带：

```http
Authorization: Bearer <session_token>
```

不要把 token 放进 URL、日志、分享链接或 localStorage。刷新页面时从 sessionStorage 恢复；如果没有凭证，重新创建会话。

### 普通对话

使用：

```http
POST /api/v1/chat/stream
Content-Type: application/json
Authorization: Bearer <session_token>
```

请求：

```json
{
  "session_id": "...",
  "message": "我的八字事业如何",
  "new_task": false,
  "birth_profile": null
}
```

使用 `fetch` + `ReadableStream` 解析 SSE，不使用原生 EventSource，因为请求需要 POST 和 Authorization。按空行切分 SSE 帧，不要假设一次网络读取就是一帧。

事件处理：

| event | 前端行为 |
|---|---|
| `start` | 保存可能首次返回的 session_id/token，初始化本次请求 |
| `route` | 显示“正在看：知识/八字/梦境/六爻”等友好标签 |
| `tool_start` | 在进度时间线上显示开始，不展示原始函数名 |
| `tool_end` | 更新对应进度为完成或失败 |
| `retrieval` | 显示“正在查找相关资料”，不要展示 chunk_id |
| `need_input` | 根据 fields 显示最小必要表单或继续提问 |
| `interrupt` | 显示六爻确认卡片，保存最新确认信息 |
| `token` | 追加到临时回答气泡；不要把 reasoning 内容展示出来 |
| `done` | 以完整 ChatResponse 覆盖临时状态，引用和状态以 done 为准 |
| `error` | 显示可操作错误，并停止 loading；不要再等待 done |

等待状态显示一条细进度时间线即可，不要让用户看到工具参数、知识库 ID、模型调用次数或内部节点名。

### 响应状态

- `answered`：正常显示回答和引用。
- `needs_input`：显示 `required_input.fields` 指定的最小资料，不要全局弹出生资料表单。
- `interrupted`：显示确认卡片，不显示“失败”。
- `cancelled`：显示取消结果，允许开始新问题。
- `blocked`：显示后端返回的安全正文，使用严肃、清晰的安全卡片，不显示传统文化装饰。

### 六爻确认卡片

当 `status=interrupted` 或收到 `interrupt` 事件时，显示：

- 已整理好的问题 `prompt`；
- `确认起卦` 主按钮；
- `修改问题` 次按钮，展开单行/多行输入；
- `先不占` 取消按钮；
- 一句说明：`确认后才会进行一次确定性起卦。`

调用：

```http
POST /api/v1/resume/stream
```

确认：

```json
{
  "session_id": "...",
  "thread_id": "...",
  "confirmation_id": "...",
  "action": "confirm"
}
```

修改时增加非空 `modification`，取消时使用 `action: "cancel"`。按钮提交后立即禁用，防止重复确认；以最新卡片里的 `confirmation_id` 为准。收到 409 时调用 session 接口恢复最新状态，并提示：`这张确认卡已经过期，我把最新问题取回来了。`

### 引用抽屉

引用只允许打开当前回答返回的引用。显示：来源标题、章节和原文；如果后端未来提供 `source_type` 再显示来源类型。加载中使用骨架屏，404 显示 `这条资料已经不在当前回答里了。` 不要显示数据库错误或 chunk_id。

## 错误与网络状态

统一处理：

- 401：`会话凭证失效，请重新开始一个会话。`
- 409：根据错误码显示“请使用当前确认卡片继续”或“确认已过期，正在刷新状态”。
- 422：在对应输入字段旁显示校验错误。
- 504：`这次整理时间有点长，先读取会话状态再继续。`
- SSE `error`：显示错误 message、重试按钮和“查看会话状态”按钮。
- 网络中断：保留用户输入和已经显示的回答片段，提供“重新连接”和“读取会话”两个操作；不要自动重复确认或自动重新起卦。

## 交互细节

- 所有主要按钮有 hover、focus、disabled、loading 状态。
- 支持键盘导航、可见 focus ring、语义化按钮和表单 label；正文对比度达到 WCAG AA。
- 移动端底部输入区不遮挡最后一条消息；键盘弹出时布局稳定。
- 回答流式生成时自动滚动只在用户已经位于底部时启用；用户上滑阅读时不要强行拉回。
- 页面刷新后恢复当前会话；浏览器返回键不应重复提交请求。
- 对话中不要自动播放声音，不要要求登录，不要强制收集出生资料。
- 所有状态文案使用中文；代码变量和 API 字段保持英文原名。

## 最终验收场景

完成后逐一验证：

1. 打开首页，不弹出生资料表单，可以发送知识问题。
2. 发送梦境问题，得到回答且不要求出生资料。
3. 发送八字问题，缺资料时只显示后端要求的字段；补全后继续。
4. 看到 route、工具、检索进度，最终回答显示安全 Markdown 和 Citation。
5. 发起六爻问题，出现确认卡片；确认只起卦一次。
6. 修改六爻问题，旧卡片失效，新卡片可继续；取消不会起卦。
7. 刷新浏览器后，凭证仍可恢复会话和确认卡片。
8. 触发 401、409、422、504 和 SSE error，页面都有清楚的恢复路径。
9. 在窄屏手机和宽屏桌面分别检查输入区、引用抽屉、确认卡片和深色模式。
10. 全站搜索确认没有“V2”“GuanChen v2”、模型名、思维链、chunk_id 或内部 Tool 名暴露给用户。

先完成可运行的主流程和真实 API 对接，再完善动效和视觉细节。不要为了展示效果引入与当前后端合同不一致的假状态。
